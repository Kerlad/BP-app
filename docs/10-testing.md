# 10. Тестирование и качество

## 10.1 Пирамида

| Уровень | Доля | Инструменты | Где |
|---|---|---|---|
| Юнит (домен, маппинг, форматтеры) | ~70% | JUnit5, kotlin.test, Turbine | `:domain`, `:core:model`, `:core:common` |
| Юнит (ViewModel, Presentation-форматтеры) | | JUnit4, kotlin.test, Turbine | модули feature |
| Интеграционные (Room, DataStore, миграции, алармы) | ~15% | JUnit4, Room testing, Robolectric | `:data:*` |
| UI / скриншоты | ~10% | JUnit4, Compose UI Test, Roborazzi | модули feature |
| E2E | ~5% | Compose UI Test на эмуляторе, 3 сценария | `:app` |

**JUnit5 — только в чистых JVM-модулях.** В Android-модулях JUnit4: Robolectric и Roborazzi
работают на JUnit4, а JUnit5 на Android требует отдельного плагина.

Юнит-тесты — на JVM, без Robolectric там, где это возможно: прогон всего набора должен
укладываться в 60 секунд, иначе их перестанут запускать локально.

## 10.2 Что обязано быть покрыто

Это не «желательно», а условие приёмки PR.

### Классификация ([06.1](06-business-logic.md#61-классификация))
Параметризованный тест с таблицей из документа + граничные значения ровно на порогах
(`135/85`, `100/60`), приоритет HIGH над LOW, реакция на смену порогов, перегрузка для `Double`
(134.5/80 → NORMAL), `pulseOutOfRange(null) == false`.

```kotlin
@ParameterizedTest
@CsvSource("120,90,HIGH", "136,70,HIGH", "135,85,HIGH", "134,84,NORMAL",
           "100,70,LOW", "145,55,HIGH", "101,61,NORMAL")
fun classify(sys: Int, dia: Int, expected: Status) {
    assertEquals(expected, classify(sys, dia, Thresholds()))
}
```

### Ввод с клавиатуры ([06.2](06-business-logic.md#62-ввод-с-клавиатуры))
Все строки таблицы тестов из документа, как последовательности нажатий. Это самая
«невидимая» логика в приложении и самая ломкая при рефакторинге.

### Статистика периода ([06.4](06-business-logic.md#64-статистика-периода))
Golden-тест на воспроизведённом датасете прототипа (seed 11, «сейчас» 2026-10-20T09:12, Europe/Moscow,
**59 записей**): средние, утро/вечер, максимум/минимум, проценты — для 7 и 30 дней.
Эталон — в `domain/src/test/resources/stats_golden.json`, получен независимым прогоном JS-логики
прототипа в Node ([06.4](06-business-logic.md#эталонные-значения)). Отдельный тест сверяет
все 59 записей генератора с выводом JS.

### Геометрия графиков ([06.5](06-business-logic.md#65-геометрия-графиков))
`yLine(50) == 190f`, `yLine(180) == 10f`, `yLine(135)`, клиппирование `yLine(200) == yLine(180)`,
`xLine(0, 1) == 174f`, равномерность при n = 14.

### Следующее напоминание ([06.6](06-business-logic.md#66-следующее-напоминание))
Все 7 дней недели × времена 00:00 / 07:59 / 08:00 / 23:59, маски «ежедневно», «Пн–Пт»,
один день, переход через воскресенье, день перехода на летнее/зимнее время (зона с DST, например
Europe/Berlin), форматы «сегодня / Завтра / Пн».

### Валидация
Границы диапазонов, `sys > dia` (включая `sys == dia`), время в будущем, пустые поля,
пульс обязателен при ручном вводе и допустим `null` при импорте.

### Миграции Room
На каждую миграцию — тест `MigrationTestHelper` c данными: записать строку в старой схеме,
миграция, прочитать и сверить. Миграция без теста не мержится. До первого релиза миграций нет —
схема v1 ([03.6](03-data-model.md#36-миграции)).

### Напоминания
`rescheduleAll()` не отменяет отложенное напоминание; деградация на `setWindow` без разрешения
на точные будильники; перепланирование после `BOOT_COMPLETED` / смены зоны ([07.6](07-reminders.md#76-тестирование)).

### Форматтеры дат
«Сегодня»/«Вчера»/«18 октября, воскресенье», «Вторник, 20 октября», склонение «измерений».
Тесты на границе суток и при `tz_offset`, отличном от текущей зоны.

### CSV (v1.1)
Полный набор фикстур и обязательных проверок — [13.6](13-csv.md#136-тесты).
Ключевое: определение кодировки и разделителя, парсер RFC 4180 (запятая и перевод строки
внутри кавычек, `""`), все форматы даты, неоднозначность `dd/MM`, дедупликация соседних минут,
round-trip экспорт → импорт, транзакционность при падении на середине файла.

## 10.3 Тесты ViewModel

Turbine + фиктивные репозитории (вручную написанные fake, не моки):

```kotlin
@Test
fun `смена порогов перекрашивает последнее измерение`() = runTest {
    val readings = FakeReadingRepository(listOf(reading(sys = 136, dia = 80)))
    val thresholds = FakeThresholdsRepository(Thresholds(highSys = 135))
    val vm = HomeViewModel(readings, thresholds, ..., clock = FIXED_CLOCK)

    vm.uiState.test {
        assertEquals(Status.HIGH, awaitItem().asContent().last!!.status)
        thresholds.set(Thresholds(highSys = 140))
        assertEquals(Status.NORMAL, awaitItem().asContent().last!!.status)
    }
}
```

Fake вместо Mockito: моки на `Flow` дают хрупкие тесты и нечитаемые ошибки.
Fake-репозитории живут в `testFixtures` и переиспользуются всеми модулями.

## 10.4 Скриншот-тесты

Roborazzi (на JVM, без эмулятора — можно гонять в CI бесплатно).

Матрица: **6 экранов × Шалфей × 2 темы = 12 эталонов** (релизное направление) плюс
Главная и Ввод для Персика и Сливы (ещё 8 — чтобы токены не ломались незаметно), плюс отдельно:
- `fontScale = 1.0 / 1.5 / 2.0` для Главной и экрана ввода (самые хрупкие по верстке);
- пустые состояния (нет измерений, фильтр без результатов, мало данных для графика);
- состояние ошибки валидации на экране ввода.

Эталоны в git (LFS не нужен: PNG 360×780 весят ~40 КБ). Расхождение > 0.1% падает CI
с визуальным diff в артефактах.

Это основной способ не потерять попиксельное соответствие хендоффу при дальнейших правках.

## 10.5 UI-тесты и E2E

Три сценария на эмуляторе (API 26, 33, 36):

1. **Запись измерения:** открыть → «Записать давление» → `1 2 8` `8 2` `7 1` → Сохранить →
   на Главной значение 128/82, тост показан.
2. **Смена порогов:** `tune` → пресет 140/90 → назад → чип последнего измерения сменил статус →
   Дневник: цвета полос пересчитаны.
3. **Напоминание:** выключить утреннее → включить дневное → проверить запланированный аларм.
   Этот сценарий — Robolectric-тест на JVM (`ShadowAlarmManager`), не на эмуляторе.

Тесты пишутся через семантику (`onNodeWithContentDescription("цифра 8")`), не через координаты.

## 10.6 Доступность

Автоматика:
- `AccessibilityChecks.enable()` в UI-тестах — ловит отсутствие `contentDescription`
  и малые цели нажатия.
- Lint-правила: `ContentDescription`, `TouchTargetSizeCheck` как `error`.

Руками (чек-лист перед релизом):
- [ ] Полный проход TalkBack по всем экранам (6 основных + настройки, онбординг, дисклеймер):
      нет узлов «Button», «Image» без описания.
- [ ] Контраст текста ≥ 4.5:1 во всех парах токенов Шалфея в обеих темах
      (особенно текст чипов статуса, см. [04.1](04-design-system.md#особенности-палитры-шалфей)).
- [ ] Цифры читаются как «128 на 82», а не «128 слэш 82».
- [ ] `fontScale = 2.0`: нет обрезанного текста, карточки растут, клавиатура работает.
- [ ] Инверсия цветов и «высокий контраст текста» не делают текст невидимым.
- [ ] Навигация с внешней клавиатуры (Tab/Enter) проходит все действия экрана ввода.

## 10.7 Производительность

| Метрика | Порог | Как мерить |
|---|---|---|
| Холодный старт до первого кадра | < 700 мс | Macrobenchmark `StartupTimingMetric`, Pixel 4a |
| Скролл дневника (2000 записей) | 0 janky frames > 16 мс на 95-м перцентиле | Macrobenchmark `FrameTimingMetric` |
| Отрисовка графика 30 дней | < 16 мс | трейс в Perfetto |
| Размер APK (release, bundle) | ≤ 12 МБ | `bundletool` + отчёт в CI |

Baseline Profile генерируется для стартового пути (Главная + экран ввода) и коммитится в репозиторий.

## 10.8 Статический анализ

| Инструмент | Настройка |
|---|---|
| ktlint | официальный Kotlin style, max line 120 |
| detekt | дефолт + правила на сложность (`CyclomaticComplexMethod` threshold 10), `ForbiddenImport` на `java.util.Date`, `ForbiddenMethodCall` на `System.currentTimeMillis`, `Instant.now`, `LocalDate.now`, `LocalDateTime.now`, `ZonedDateTime.now` (кроме `SystemTimeProvider`) |
| Android Lint | `warningsAsErrors = true`, baseline только для внешних зависимостей |
| Compose-правила | `compose-rules` от Twitter/slack: запрет изменяемого состояния в параметрах, запрет `ViewModel` внутри вложенных composable |

## 10.9 CI (GitHub Actions)

```yaml
on: [pull_request, push]
jobs:
  check:
    steps:
      - setup-java 21, gradle cache
      - ./gradlew ktlintCheck detekt lintDebug
      - ./gradlew testDebugUnitTest            # домен + ViewModel
      - ./gradlew verifyRoborazziDebug         # скриншоты
      - ./gradlew assembleDebug
      - upload-artifact: отчёты, diff скриншотов
  instrumented:
    runs-on: ubuntu-latest (эмулятор API 33)
    steps:
      - ./gradlew connectedDebugAndroidTest    # E2E + миграции
```

PR не мержится при красном `check`. `instrumented` — обязателен на `main`, на PR допускается
в ночном прогоне, если время сборки станет проблемой.
