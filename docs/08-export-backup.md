# 08. Экспорт и резервное копирование

Три разных сценария, которые часто путают:

| Сценарий | Кому | Формат | Приоритет |
|---|---|---|---|
| **Экспорт** — «показать врачу» | человеку | CSV и PDF (PDF обязателен — решение заказчика) | P1 (v1.1) |
| **Импорт** — «перенести из другого дневника» | из чужого формата | CSV любого диалекта | P1 (v1.1) |
| **Бэкап** — «не потерять при смене телефона» | приложению | JSON-архив | P1 (v1.1) |
| **Перенос на новый телефон** | системе Android | device-to-device transfer | MVP |

Облачный бэкап Android **выключен**, перенос «телефон → телефон» средствами Android — **включён**,
см. [09.5](09-privacy-security.md#95-бэкапы-android).

## 8.1 CSV

Спецификация импорта и экспорта вынесена в отдельный документ: **[13. CSV](13-csv.md)**.
Там же образцы файлов в `docs/samples/` и набор тестовых фикстур.

Коротко:

- **Экспорт — один канонический формат**, без настроек: `;`, UTF-8 с BOM, CRLF, заголовок
  по-русски, шапка `#` с порогами, последняя колонка `Метка времени` (ISO 8601 со смещением)
  для обратного импорта без потерь.
- **Импорт — толерантный**: сам определяет кодировку (UTF-8 с BOM и без, Windows-1251),
  разделитель (`,` `;` `\t` `|`), наличие заголовка, порядок колонок и формат даты.
  Полноценный парсер RFC 4180 — запятая и перевод строки внутри закавыченного комментария
  не ломают разбор.
- **Round-trip гарантирован тестом**: экспорт → импорт → данные идентичны.

Файл отдаётся через `ACTION_CREATE_DOCUMENT` (SAF) — приложению не нужны разрешения на хранилище.
Второй путь — «Поделиться» через `FileProvider` + `ACTION_SEND` (отправить врачу в мессенджер).
Имя файла: `davlenie_2026-09-20_2026-10-20.csv`.

## 8.2 Экспорт PDF (v1.1)

Обязателен в v1.1 (решение заказчика). Отчёт для распечатки:
шапка (период, пороги — **без имени**, имени в приложении нет), график за период, блок статистики,
таблица измерений. Выбор периода — как у CSV: 7 / 30 / 90 дней / всё время / произвольный.
Генерация — `PdfDocument` + отрисовка в `Canvas` (те же формулы геометрии из
[06.5](06-business-logic.md#65-геометрия-графиков)), без сторонних библиотек.
Таблица при >50 записях переносится на следующие страницы.

Печать — через `PrintManager`, чтобы работала отправка на принтер и «Сохранить как PDF».

## 8.3 Резервная копия

```json
{
  "format": "bp-diary-backup",
  "version": 1,
  "exportedAt": "2026-10-20T09:12:00Z",
  "thresholds": { "highSys": 135, "highDia": 85, "lowSys": 100, "lowDia": 60,
                  "pulseLow": 50, "pulseHigh": 90 },
  "settings": { "themeMode": "SYSTEM", "direction": "SAGE", "lastArm": "LEFT" },
  "reminders": [ { "time": "08:00", "label": "Утреннее измерение",
                   "days": ["MON","TUE","WED","THU","FRI","SAT","SUN"], "enabled": true } ],
  "readings": [ { "takenAt": "2026-10-20T07:24:00Z", "tzOffset": 10800,
                  "sys": 128, "dia": 82, "pulse": 71, "arm": "LEFT",
                  "tags": ["HEADACHE"], "comment": "" } ]
}
```

- `id` не экспортируются — при импорте выдаются новые.
- Теги — ключами `Tag` ([03.1](03-data-model.md#31-доменные-модели-coremodel-без-android-зависимостей)); `pulse` может быть `null`.
- Удалённые (soft delete) записи не экспортируются.
- Файл сохраняется через SAF; имя `bp-diary-backup-2026-10-20.json`.
- Размер: ~150 байт на запись, 5 лет по 2 измерения в день ≈ 550 КБ. Сжатие не нужно.

### Импорт

1. Выбор файла (`ACTION_OPEN_DOCUMENT`, `application/json`).
2. Разбор и валидация: неизвестный `format` → ошибка; `version` больше текущей → «Файл
   из более новой версии приложения».
3. Экран подтверждения: «В файле 1 240 измерений за период 15.03.2024 — 20.10.2026.
   Что сделать?» → **Добавить к имеющимся** / **Заменить всё**.
   - «Добавить к имеющимся» — импортируются **только измерения**; пороги, напоминания и настройки
     остаются текущими.
   - «Заменить всё» — измерения удаляются физически и заменяются, пороги, напоминания и настройки
     берутся из файла (после валидации, как при ручном вводе).
4. **Дедупликация при добавлении:** запись считается дублем, если совпадают `takenAt` (с точностью
   до минуты), `sys`, `dia`, `pulse`. Дубли пропускаются, в итоге показывается
   «Добавлено 320, пропущено 920 дублей».
5. Вся операция — в одной транзакции Room. Прерывание на середине не оставляет полуимпорт.
6. После импорта — `rescheduleAll()` для напоминаний.

### Критично

Импорт JSON и импорт CSV ([13](13-csv.md)) — два места, где приложение читает внешний файл.
Правила общие для обоих:
- Парсинг через `kotlinx.serialization` с `ignoreUnknownKeys = true`, но **без** доверия к значениям:
  каждое измерение проходит ту же валидацию, что ручной ввод ([03.7](03-data-model.md#37-валидация-на-входе-в-data-слой)).
  Невалидные записи пропускаются и показываются счётчиком, а не роняют импорт.
- Ограничение размера файла: 20 МБ. Больше — отказ с внятным текстом.
- Чтение потоковое, чтобы 100 000 записей не положили процесс по памяти. `Json.decodeFromStream`
  для этого **не подходит** (строит весь объект целиком): массив `readings` читается поэлементно —
  `Json.decodeToSequence` по массиву или ручной разбор через `JsonReader`, запись пачками внутри
  одной транзакции.

## 8.4 Миграция на новый телефон

MVP: перенос средствами Android при настройке нового телефона (кабель / «Быстрый перенос»,
device-to-device transfer) — база и настройки включены в `<device-transfer>`, облачный бэкап
выключен ([09.5](09-privacy-security.md#95-бэкапы-android)). Ограничение: работает только при переносе
через мастер настройки Android, не при восстановлении из облачной копии.

v1.1: явная резервная копия JSON ([8.3](#83-резервная-копия)) — «Сделайте резервную копию
в облако/мессенджер → восстановите на новом телефоне».

Оба сценария описываются в «О приложении» одним абзацем — люди 50+ реально теряют данные
при смене телефона, и это главная причина однозвёздочных отзывов у аналогов.

v2: синхронизация через Google Drive App Folder (`DriveScopes.DRIVE_APPDATA`) —
данные остаются в приватной папке приложения, своего сервера не появляется.
