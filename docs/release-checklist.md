# Чек-лист релиза

Сводит [09.7](09-privacy-security.md#97-чек-лист-перед-релизом) и [11.5](11-build-release.md#115-release-чек-лист) с учётом
решений D-03 (без SQLCipher), D-04 (без сторонних SDK и без `INTERNET`) и D-12 (только `SCHEDULE_EXACT_ALARM`).

**Загрузку в Play Console делает владелец приложения, не разработка.** В репозитории есть только сборка подписанного
bundle (`.github/workflows/release.yml`), загрузки в Play там нет.

Условные обозначения: **авто** — проверяется командой или в CI, **сделано** — выполнено при разработке, **вручную** — нужно
сделать до релиза, **вопрос** — нужен ответ заказчика.

## 1. Сборка и подпись

| Пункт | Статус |
|---|---|
| Release-сборка проходит R8 (`isMinifyEnabled`, `isShrinkResources`), правила в `app/proguard-rules.pro`: маршруты навигации (`@Serializable`) и имена рабочих классов WorkManager | **авто**: `./gradlew assembleRelease` |
| Минифицированная сборка запускается: Главная, ввод, вкладки, прокрутка 2 000 записей (проверено на эмуляторе 2026-10-29 через сборку `benchmark`, она наследует настройки release) | **сделано**; перед релизом повторить на телефоне |
| Размер bundle ≤ 12 МБ. На 2026-10-29: bundle 4,85 МБ, APK 2,08 МБ | **вручную**: пересмотреть перед релизом |
| Подпись: ключ загрузки (upload key) не в git. Локально `keystore.properties` (в `.gitignore`), в CI секреты `BP_KEYSTORE_BASE64`, `BP_STORE_PASSWORD`, `BP_KEY_ALIAS`, `BP_KEY_PASSWORD` | **вручную**: создать ключ и секреты |
| Play App Signing включён, upload key отдельный от ключа приложения | **вручную** в Play Console |
| **Резервная копия keystore** в надёжном месте. Потеря upload key при Play App Signing восстановима, потеря ключа подписи приложения нет | **вручную**, обязательно до первого релиза |
| `versionCode` растёт сам: число коммитов (`BP_VERSION_CODE`), `versionName` из тега `v1.0.0` (`BP_VERSION_NAME`). Руками не правится. Локальный дефолт `0.1.0` | **авто** в `release.yml`; тег `v1.0.0` поставить при релизе |
| Changelog заполнен | **вручную** |
| `./gradlew clean check connectedDebugAndroidTest` зелёный (`check` включает `verifyReleaseManifest`) | **вручную**: команда на машине с эмулятором; в CI те же проверки по частям |

## 2. Приватность и разрешения ([09.7](09-privacy-security.md#97-чек-лист-перед-релизом))

| Пункт | Статус |
|---|---|
| В итоговом манифесте нет `INTERNET`, `USE_EXACT_ALARM`, `FOREGROUND_SERVICE`, нет разрешённого cleartext-трафика | **авто**: `./gradlew verifyReleaseManifest` (в CI и в `check`) |
| Список разрешений release: `SCHEDULE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`, `POST_NOTIFICATIONS`, плюс `WAKE_LOCK` и `ACCESS_NETWORK_STATE` от WorkManager (обычные, без запроса) | **сделано**, проверено 2026-10-29 |
| Служба WorkManager для переднего плана и её разрешение убраны из манифеста (иначе Play потребует декларацию о foreground-службах) | **сделано** |
| D-04: нет сторонних SDK во время работы (Firebase, аналитика, крэш-репорты) | **вручную**: просмотреть `./gradlew :app:dependencies --configuration releaseRuntimeClasspath` |
| D-03: база без шифрования (Room без SQLCipher). Данные только на устройстве, облачный бэкап выключен | **сделано**, это решение заказчика; учесть в формулировках Data Safety |
| Бэкап по D-16: облако исключает всё, перенос «телефон в телефон» включает базу и настройки (`data_extraction_rules.xml`, `full_backup_content.xml`) | **сделано**; **вручную** проверить `adb shell bmgr backupnow <пакет>`: база не должна уходить в облачный транспорт |
| Release-сборка не пишет значения измерений в лог | **вручную**: прогнать сценарии и посмотреть `adb logcat` |
| «Удалить все данные» удаляет всё: измерения (в том числе мягко удалённые), напоминания, настройки, алармы | **авто**: тесты `DeleteAllDataUseCaseTest` и проверка на настоящей базе Room; **вручную** один раз проверить на телефоне дампом базы |
| Дисклеймер подтверждается при первом запуске, показывается снова при росте `DISCLAIMER_VERSION`, дословно из docs/09 §9.6 | **авто**: тесты шлюза и экранов |
| Дисклеймер в первом абзаце описания в Play | **вручную** |
| Политика конфиденциальности опубликована, ссылка в Play и в «О приложении» | **вопрос**: нужен адрес. Пока `about_privacy_url` пуст в `feature/settings/src/main/res/values/strings.xml`, строка в «О приложении» скрыта |

## 3. Напоминания (D-12)

| Пункт | Статус |
|---|---|
| Объявлено только `SCHEDULE_EXACT_ALARM`; без него будильник идёт в окне 10 минут, на экране напоминаний баннер | **авто**: тесты планировщика и сценарий напоминания |

| `POST_NOTIFICATIONS` на Android 13+: запрос в онбординге, баннер при отказе, после второго отказа переход в настройки | **сделано**; **вручную** проверить системный диалог на телефоне |

## 5. Play Console (делает владелец)

- **Категория:** Health & Fitness (не Medical).
- **Листинг:** короткое описание до 80 знаков; полное: что делает, затем дисклеймер ([09.6](09-privacy-security.md#96-медицинские-дисклеймеры)),
  функции списком, в конце «Все данные хранятся только на вашем телефоне». Шесть скриншотов в «Шалфее», светлая тема, плюс один
  тёмный, значения реалистичные, без «идеальных» 120/80 везде, приветствие без имени.
- **Data Safety:** данные не собираются и не передаются (всё остаётся на устройстве, [09.4](09-privacy-security.md#94-google-play-data-safety)).
  Способ удалить данные: «Настройки → Удалить все данные».
- **Декларация Health apps:** отслеживание показателей здоровья, без медицинской функции, данные только на устройстве.
- **Политика конфиденциальности:** обязательный адрес (см. выше, **вопрос**).
- **Целевая аудитория:** 18+, приложение не для детей.
- **Закрытое тестирование:** не меньше 12 тестеров непрерывно 14 дней до доступа к production, рассчитывать заранее
  (для личных аккаунтов разработчика, созданных после ноября 2023). Внутреннее тестирование 1–2 дня перед ним.
- **Выпуск:** поэтапно 10 % → 50 % → 100 % с интервалом 2–3 дня; следить за crash-free rate ≥ 99,5 % и ANR в Android vitals.
- Файл `mapping.txt` из артефакта `release-bundle` загрузить вместе с bundle, чтобы трассы в Android vitals читались.
