# 09. Приватность, безопасность, медицинские требования

Приложение хранит **данные о здоровье**. Это особая категория и в GDPR, и в 152-ФЗ,
и в политиках Google Play. Решения ниже выбраны так, чтобы юридическая нагрузка была минимальной.

## 9.1 Главный принцип: данные не покидают устройство

| Решение | Следствие |
|---|---|
| Нет разрешения `INTERNET` в MVP | приложение физически не может передать данные; это проверяемый факт для ревью и для отзывов |
| Нет аккаунта, нет регистрации | нет персональных данных у разработчика → нет обязанностей оператора ПД |
| Нет аналитики и крэш-репортов, нет сторонних SDK | решение заказчика, см. 9.3 |
| Нет рекламы | рекламные SDK собирают идентификаторы; с медицинскими приложениями это конфликт |

Как только появится облачная синхронизация (v2), появятся: политика конфиденциальности
с описанием обработки, согласие пользователя, DPA с провайдером, шифрование на клиенте.
До тех пор — ничего из этого не нужно, и это серьёзная экономия.

## 9.2 Шифрование локальной базы

**Решение заказчика: без SQLCipher.** Обычный Room.

Данные о здоровье в открытой SQLite доступны только с root или через adb-бэкап. Поэтому:
- облачный бэкап Android выключен ([9.5](#95-бэкапы-android));
- в кэше и внешнем хранилище данные измерений не хранятся (временные файлы экспорта/импорта
  удаляются сразу после операции);
- в release нет логирования значений ([9.3](#93-аналитика-и-крэш-репорты)).

Если шифрование понадобится после релиза — это отдельная задача с миграцией базы в SQLCipher
(+~3 МБ APK); при планировании учесть, что device-to-device перенос зашифрованной базы требует
переноса ключа, а ключ из Android Keystore не переносится.

**Блокировка входа (v1.1):** опционально `BiometricPrompt` при запуске.
Важный нюанс: это защита от «посмотреть телефон», не от извлечения данных —
не обещать больше в описании.

## 9.3 Аналитика и крэш-репорты

**Решение заказчика: без сторонних SDK** — ни Crashlytics, ни ACRA, ни аналитики. Приоритет —
лёгкий быстрый запуск. Разрешения `INTERNET` нет, отправлять данные приложению физически нечем.

Источник информации о сбоях — **Android vitals в Play Console** (крэши и ANR собирает система,
без кода в приложении и без медицинских данных).

Запрещено:
- Передача `sys`/`dia`/`pulse`/комментариев/тегов куда-либо.
- Логирование измерений в `Logcat` в release-сборке. В debug — за флагом.

```kotlin
// своя тонкая обёртка над android.util.Log, без Timber.
// d() работает только в debug; w()/e() пишутся всегда, но в них запрещено передавать значения измерений.
object BpLog {
    fun d(tag: String, msg: () -> String) { if (BuildConfig.DEBUG) Log.d(tag, msg()) }
    fun w(tag: String, msg: String, t: Throwable? = null) { Log.w(tag, msg, t) }
    fun e(tag: String, msg: String, t: Throwable? = null) { Log.e(tag, msg, t) }
}
```

Согласия на крэш-репорты в онбординге **нет**.

## 9.4 Google Play Data Safety

Заполняется так (при MVP без сети):

| Пункт | Ответ |
|---|---|
| Does your app collect or share any of the required user data types? | **Нет.** Данные, которые обрабатываются только на устройстве и никуда не передаются, в Data Safety не декларируются как «собираемые» |
| Is all of the user data encrypted in transit? | н/п (нет передачи) |
| Do you provide a way for users to request that their data be deleted? | н/п при «не собираем»; в описании и политике указать: «Настройки → Удалить все данные» |

Отдельно в Play Console заполняется **декларация Health apps** (Health apps declaration form):
категория — отслеживание показателей здоровья, без медицинской функциональности, данные только на устройстве.

Нужен публичный URL политики конфиденциальности — даже без сбора данных Play его требует
для категории Health & Fitness / Medical. Политика на одну страницу: что хранится,
где (только на устройстве), как удалить, контакт.

Функция **«Удалить все данные»** в настройках обязательна уже в MVP: физическая очистка Room
(включая soft-deleted) + DataStore + отмена всех алармов (включая отложенный), с двойным диалогом
подтверждения ([05.7](05-screens.md#57-настройки)).

## 9.5 Бэкапы Android

```xml
<application
    android:allowBackup="true"
    android:dataExtractionRules="@xml/data_extraction_rules"
    android:fullBackupContent="@xml/full_backup_content">
```

```xml
<!-- res/xml/data_extraction_rules.xml (API 31+) -->
<data-extraction-rules>
    <cloud-backup>
        <exclude domain="root" path="." />
        <exclude domain="database" path="." />
        <exclude domain="sharedpref" path="." />
        <exclude domain="file" path="." />
    </cloud-backup>
    <device-transfer>
        <include domain="database" path="bp.db" />
        <include domain="file" path="datastore/settings.preferences_pb" />
    </device-transfer>
</data-extraction-rules>

<!-- res/xml/full_backup_content.xml (API ≤ 30): исключить всё -->
<full-backup-content>
    <exclude domain="root" path="." />
    <exclude domain="database" path="." />
    <exclude domain="sharedpref" path="." />
    <exclude domain="file" path="." />
</full-backup-content>
```

Почему так:
- **Облачный бэкап выключен** — автобэкап складывает базу в Google Drive пользователя в открытом виде.
- **Перенос «телефон → телефон» включён** — это единственный способ не потерять данные при смене
  телефона в MVP (JSON-бэкап — только v1.1). Перенос идёт напрямую между устройствами, без облака.
- На API ≤ 30 разделения на облако/перенос нет, поэтому там исключено всё; для этих версий
  перенос — только через JSON-бэкап (v1.1).
- Проверить вручную: `adb shell bmgr backupnow <pkg>` не должен выгружать базу в облачный транспорт.

Также:
- `android:excludeFromRecents="false"`, но на экране ввода и дневнике —
  `FLAG_SECURE`? **Нет**: это ломает скриншоты, которые пользователь делает, чтобы отправить
  врачу. Вместо флага — ничего. Решение осознанное: удобство здесь важнее.

## 9.6 Медицинские дисклеймеры

Google Play отклоняет приложения, которые заявляют диагностику без сертификации.
Поэтому формулировки везде строго описательные.

**Можно:** «записывайте измерения», «отмечайте значения за пределами ваших уровней»,
«показывайте историю врачу», «следите за динамикой».

**Нельзя:** «определяет гипертонию», «диагностика», «норма давления» как медицинское
утверждение, «безопасно/опасно», «снизит давление», «измеряет давление по камере».

### Обязательные места с дисклеймером

| Где | Текст |
|---|---|
| Онбординг, экран с чекбоксом | «Дневник давления помогает вести записи и не является медицинским прибором. Он не ставит диагноз и не заменяет консультацию врача. Все решения о лечении принимает врач.» |
| Экран «Уровни» | «Целевые значения согласуйте с лечащим врачом.» (уже в хендоффе) |
| «О приложении» | полный текст + «При резком ухудшении самочувствия обратитесь за медицинской помощью» |
| Описание в Play | дисклеймер в первом абзаце |

`disclaimer_ack` в DataStore хранит **номер версии** принятого дисклеймера (`Int`). В коде —
константа `DISCLAIMER_VERSION` (сейчас 1). Если сохранённое значение меньше — экран показывается снова.

### Критические значения

Если введено измерение с САД ≥ 180 или ДАД ≥ 120 — после сохранения показывается **не диагноз**,
а нейтральная подсказка. Один раз на запись, закрывается кнопкой «Понятно».

Заказчик предложил формулировку «Значения выше/ниже установленной нормы». В таком виде её
использовать нельзя: слово «норма» как медицинское утверждение запрещено (см. «Нельзя» выше),
а для «ниже» не задан порог. Рабочий текст (**ожидает подтверждения заказчика**):

> «Значение заметно выше ваших обычных уровней. Если самочувствие ухудшилось — обратитесь
> за медицинской помощью.»

Только для высоких значений; нижний критический порог не вводится, пока заказчик его не задаст.

## 9.7 Чек-лист перед релизом

- [ ] В манифесте нет `INTERNET` (проверить итоговый манифест после merge — библиотеки могут его добавить).
- [ ] Облачный бэкап исключает всё, device-transfer включает только базу и настройки (9.5).
- [ ] Release-сборка не логирует измерения (проверить `logcat` на реальном прогоне).
- [ ] ProGuard/R8 включён, `-keepclassmembers` только для моделей сериализации.
- [ ] Политика конфиденциальности опубликована, ссылка в Play и в «О приложении».
- [ ] Дисклеймер подтверждается в онбординге и присутствует в описании Play.
- [ ] «Удалить все данные» действительно удаляет всё (проверить дампом базы после операции).
- [ ] Нет сторонних SDK в runtime-зависимостях (`./gradlew :app:dependencies` — только AndroidX/Kotlin/Hilt).
- [ ] Data Safety и декларация Health apps заполнены (9.4).
