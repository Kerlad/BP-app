# 01. Требования

## 1.1 Задача продукта

Человек с гипертонией (или назначенным контролем давления) должен **за 15 секунд** записать
измерение и **за один взгляд** понять, как дела за неделю. Второе — показать врачу внятную
историю вместо бумажной тетради.

Приложение **не диагностирует и не лечит**. Оно фиксирует, классифицирует по уровням, которые
пользователь согласовал со врачом, и напоминает.

## 1.2 Границы MVP

**Входит:**
- Ручной ввод измерения: САД, ДАД, пульс, рука, время, теги самочувствия, комментарий.
- Дневник с группировкой по дням и фильтром по статусу.
- Графики 7/30 дней + блок статистики.
- Напоминания по времени и дням недели.
- Пользовательские уровни (пороги) давления и пульса + пресеты.
- Редактирование и удаление записи (с «Отменить»), без истории изменений.
- Светлая/тёмная тема, цветовое направление **Шалфей** (решение заказчика, см. [12.7](12-roadmap-backlog.md#127-реестр-решений)).
- Минимальные настройки: тема, «Удалить все данные», «О приложении».
- Полностью локальное хранение, перенос на новый телефон через device-to-device transfer ([09.5](09-privacy-security.md#95-бэкапы-android)).

**Не входит в MVP** (см. [роадмап](12-roadmap-backlog.md)):
Bluetooth-тонометры, облачная синхронизация, несколько профилей, Health Connect,
приём лекарств, вес/шаги, экспорт CSV/PDF (v1.1), виджеты, Wear OS.

## 1.3 Роли

Одна роль — **пользователь**. Многопрофильность (например, муж+жена на одном телефоне) —
v2, но модель данных должна её допускать (см. [03](03-data-model.md), поле `profileId`).

## 1.5 Функциональные требования

### FR-1. Ввод измерения
1. Поля: САД (целое), ДАД (целое), пульс (целое). Максимум 3 цифры на поле.
2. Собственная цифровая клавиатура 3×4 (системная не используется).
3. Автопереход между полями по правилу из [06](06-business-logic.md#62-ввод-с-клавиатуры).
4. Кнопка «Сохранить» неактивна, пока все три поля не заполнены.
5. Валидация при сохранении: САД 50…300, ДАД 30…200, пульс 25…250, САД > ДАД.
   Нарушение → обводка поля цветом `hi`, под сеткой полей одна строка объяснения, сохранение блокируется.
6. Рука: «Левая»/«Правая», последний выбор запоминается и подставляется.
7. Теги самочувствия — мультивыбор из фиксированного списка 6 штук (хранятся стабильными ключами, см. [03.1](03-data-model.md#31-доменные-модели-coremodel-без-android-зависимостей)).
8. Комментарий — до 120 символов.
9. Время по умолчанию — «сейчас»; в v1.1 можно изменить дату/время (не в будущем).
10. После сохранения новой записи: переход на Главную + тост «Измерение сохранено» на 2.4 с.
    После сохранения правки: возврат на предыдущий экран + тост «Изменения сохранены».
11. Если САД ≥ 180 или ДАД ≥ 120 — после сохранения нейтральная подсказка ([09.6](09-privacy-security.md#критические-значения)).

### FR-2. Дневник
1. Записи сгруппированы по календарным дням, свежие сверху.
2. Заголовки групп: «Сегодня», «Вчера», иначе «18 октября, воскресенье».
3. Фильтры: Все / Повышенное / Норма / Пониженное.
4. Пустое состояние с фильтром: «Нет измерений с такой отметкой».
5. Пустое состояние без записей вообще: пояснение + кнопка «Записать давление».
6. Тап по записи → просмотр/редактирование; свайп или меню → удалить с «Отменить» (snackbar, 5 с).
7. Пагинация постранично (Paging 3 или `LIMIT`-порции по 50): история может быть на годы.

### FR-3. Графики и статистика
1. Периоды 7 и 30 дней (v1.1 — 90 дней и «всё время»).
2. Линии САД и ДАД по каждому измерению, пунктирные линии пользовательских порогов.
3. Ось Y фиксирована 50…180 мм рт. ст.; значения вне диапазона клиппируются (см. [06](06-business-logic.md)).
4. Блок статистики: среднее, средний пульс, утро (<12:00), вечер (≥12:00), максимум и минимум по САД с датой.
5. Блок «В пределах ваших уровней»: процент норм + полоса из трёх сегментов + счётчики.
6. Если в периоде < 2 измерений — график заменяется текстом «Мало данных для графика», статистика скрывается.

### FR-4. Напоминания
1. Список напоминаний: время, название, дни недели, переключатель.
2. Предзаполнено тремя: 08:00 Утреннее (ежедневно, вкл), 14:00 Дневное (Пн–Пт, выкл), 21:00 Вечернее (ежедневно, вкл).
3. Добавление/редактирование: Material time picker + выбор дней недели + название.
4. Уведомление с действием «Записать» → открывает экран ввода.
5. Переживает перезагрузку устройства и обновление приложения.
6. Если разрешение на уведомления не выдано — на экране напоминаний баннер с кнопкой «Разрешить».

### FR-5. Уровни (пороги)
1. Пресеты: 135/85 «Домашние измерения», 140/90 «Измерения у врача» — меняют только высокие САД/ДАД.
2. Степперы с шагом 5: высокое САД/ДАД, низкое САД/ДАД, границы нормального пульса.
3. Допустимые границы: высокое САД 110…200, высокое ДАД 70…130, низкое САД 70…120,
   низкое ДАД 40…90, пульс 30…200. Низкий порог не может быть ≥ высокого.
4. Изменение порогов **пересчитывает** цвета во всём приложении немедленно (статус не хранится в БД).
5. Сноска: «Целевые значения согласуйте с лечащим врачом.»

### FR-6. Настройки
**MVP:** тема (системная/светлая/тёмная), «Удалить все данные», «О приложении» с дисклеймером,
версией и ссылкой на политику конфиденциальности. Вход — видимый пункт «Настройки» на экране «Уровни».
**v1.1:** размер шрифта, экспорт CSV/PDF, импорт CSV, резервная копия JSON.
Выбор цветового направления в UI не предусмотрен (релизится Шалфей).

### FR-7. Импорт и экспорт CSV (v1.1)
Полная спецификация — [13. CSV](13-csv.md).

1. **Экспорт** в один канонический формат (без выбора настроек пользователем):
   `;`, UTF-8 с BOM, CRLF, русский заголовок, шапка `#` с действующими порогами,
   завершающая колонка `Метка времени` в ISO 8601 со смещением.
2. Диапазон экспорта: 7 / 30 / 90 дней / всё время / произвольный период.
3. **Импорт** принимает CSV из сторонних приложений: автоопределение кодировки
   (UTF-8 с BOM и без, Windows-1251), разделителя (`,` `;` `\t` `|`), наличия заголовка,
   порядка колонок и формата даты. Парсер соответствует RFC 4180.
4. Перед записью — экран предпросмотра с ручной правкой сопоставления колонок.
5. Стратегии: «Добавить к имеющимся» (с дедупликацией) и «Заменить все данные».
6. Дубль — совпадение времени с точностью до минуты и всех трёх значений. Измерения
   в соседние минуты с разными значениями дублями **не** считаются.
7. Невалидные строки пропускаются с отчётом, а не прерывают импорт. Операция транзакционна.
8. Round-trip: экспорт → импорт восстанавливает данные без потерь (проверяется тестом).

### FR-8. Отчёт PDF для врача (v1.1)
Обязателен в v1.1 (решение заказчика). Спецификация — [08.2](08-export-backup.md#82-экспорт-pdf-v11).

## 1.6 Нефункциональные требования

| Категория | Требование |
|---|---|
| Производительность | Холодный старт до первого кадра Главной < 700 мс на Pixel 4a; графики на 2000 измерениях рендерятся < 16 мс/кадр |
| Отзывчивость | Нажатие клавиши цифровой клавиатуры → отрисовка цифры < 50 мс; без скачков layout |
| Надёжность | Потеря данных недопустима: запись подтверждается только после коммита транзакции Room |
| Офлайн | 100% функций без сети; приложение не имеет разрешения `INTERNET` в MVP |
| Доступность | TalkBack читает цифры как «128 на 82»; все цели нажатия ≥ 48 dp; контраст ≥ 4.5:1 для текста; поддержка системного масштаба шрифта до 200% |
| Локализация | MVP: русский. Строки сразу в `strings.xml`, без хардкода; плюрализация через `plurals` |
| Размер | APK ≤ 12 МБ (шрифт Golos Text — только нужные начертания 400/500/600/700, локально) |
| Совместимость | minSdk 26, targetSdk 36; проверка на 8.0, 11, 14, 16 |
| Приватность | Данные только на устройстве; никаких сторонних SDK, аналитики и крэш-репортов (решение заказчика) |

## 1.7 Критерии приёмки MVP

- [ ] Запись измерения от открытия приложения до тоста — ≤ 2 нажатий помимо цифр
      («Записать давление» + «Сохранить»/`check`; для 128/82/71 это 9 нажатий всего), ≤ 15 с.
- [ ] Пороги менялись → цвета в дневнике и графике соответствуют новым порогам без перезапуска.
- [ ] Напоминание срабатывает после reboot и после force-stop + reboot.
- [ ] 30 дней демо-данных: графики, статистика и проценты совпадают с эталонными значениями из юнит-тестов.
- [ ] Светлая и тёмная темы соответствуют хендоффу попиксельно по токенам (ревью с дизайнером).
- [ ] TalkBack-проход по всем экранам без «немых» элементов.
- [ ] Поворот экрана и смена темы не теряют черновик ввода.
