# 13. CSV: импорт и экспорт

Асимметричная задача, и это нормально:

- **Импорт — толерантный.** Файл приходит из чужого приложения, из Excel, из заметок. Диалект заранее
  неизвестен. Задача — прочитать как можно больше строк и внятно сказать про остальные.
- **Экспорт — один канонический формат.** Никаких настроек и вариантов: один предсказуемый файл,
  который открывается в Excel, читается человеком и возвращается обратно без потерь.

## 13.1 Референсный файл импорта

`docs/samples/import-sample-ru-comma.csv` — обезличенная копия реального экспорта из сторонней
программы (структура один-в-один, значения изменены). Разбор оригинала:

| Свойство | Значение | Чем опасно |
|---|---|---|
| Кодировка | UTF-8 **без BOM** | Excel-экспорт даёт BOM, а этот файл — нет. Нельзя требовать BOM |
| Переводы строк | LF | CRLF тоже встречается, нужно принимать оба |
| Разделитель | **запятая** | Мой первоначальный экспорт был на `;` — импорт обязан определять разделитель сам |
| Кавычки | **все** поля закавычены | Числа приходят как `"117"`, а не `117` |
| Заголовок | **отсутствует** | Колонки определяются позиционно/эвристикой |
| Колонок | 5: дата-время, САД, ДАД, пульс, комментарий | Нет колонок «рука» и «теги» |
| Дата | `dd.MM.yyyy HH:mm` одним полем | Не ISO, без часового пояса |
| Запятая внутри поля | есть: `"суббота, до приёма"` | `split(",")` ломается — нужен парсер RFC 4180 |
| Рука | только текстом в комментарии: `"левая"` | Эвристика + явное согласие пользователя |
| Хвост | пустая последняя строка | Пустые строки пропускаются молча |
| Записи в минуту друг от друга | `06:49 118/83` и `06:50 121/86` | Контрольное измерение. Дедупликация **не** имеет права их склеить |

Эти 27 строк — обязательная фикстура: импорт должен давать ровно 27 записей, 0 ошибок,
1 запись с автоопределённой левой рукой.

## 13.2 Импорт

### Этапы

```
файл (SAF) → кодировка → диалект → RFC-4180-парсер → маппинг колонок
           → разбор даты → валидация строк → предпросмотр → стратегия слияния → транзакция
```

Ни один этап не падает целиком из-за одной плохой строки: ошибки собираются в отчёт.

### Кодировка

1. Снять BOM, если есть (UTF-8 / UTF-16LE / UTF-16BE).
2. Попытка UTF-8 **строгая** (`CodingErrorAction.REPORT`).
3. При ошибке — Windows-1251 (так отдаёт русский Excel «Сохранить как CSV»).
4. При ошибке — предложить выбор кодировки вручную в предпросмотре.

```kotlin
fun detectCharset(head: ByteArray): Charset = when {
    head.startsWith(BOM_UTF8)    -> UTF_8
    head.startsWith(BOM_UTF16LE) -> UTF_16LE
    head.startsWith(BOM_UTF16BE) -> UTF_16BE
    decodesStrictly(head, UTF_8) -> UTF_8
    else                         -> charset("windows-1251")
}
```

### Определение диалекта

На первых 20 непустых строках:

- **Разделитель:** из кандидатов `, ; \t |` выбирается тот, который даёт одинаковое количество
  полей на максимуме строк (и это количество > 1). При равенстве приоритет: `;`, `,`, `\t`, `|`.
  Считаются только вхождения **вне кавычек**.
- **Заголовок:** первая строка считается заголовком, если в позициях, где в остальных строках
  стоят целые числа, у неё нечисловые значения.
- **Кавычки:** всегда обрабатываются по RFC 4180 (`""` внутри поля — одна кавычка),
  независимо от того, закавычен файл целиком или нет.
- **Строки, начинающиеся с `#`** — пропускаются (это метаданные нашего же экспорта).

### Парсер

Своя конечная автомат-реализация, без сторонних библиотек: потоковая, без регулярок,
корректная на кавычках, переводах строк внутри полей и `""`.

```kotlin
class CsvReader(private val reader: Reader, private val delimiter: Char) {
    fun rows(): Sequence<List<String>> = sequence {
        val field = StringBuilder(); val row = mutableListOf<String>()
        var inQuotes = false
        var afterQuote = false      // внутри кавычек встретили '"': это либо "", либо конец кавычек
        var afterCr = false         // предыдущий символ вне кавычек — '\r'

        fun endField() { row += field.toString(); field.setLength(0) }
        suspend fun SequenceScope<List<String>>.endRow() {
            endField()
            if (!(row.size == 1 && row[0].isEmpty())) yield(row.toList())   // пустая строка — пропуск
            row.clear()
        }

        while (true) {
            val c = reader.read()
            if (c == -1) break
            var ch = c.toChar()

            if (afterQuote) {
                afterQuote = false
                if (ch == '"') { field.append('"'); continue }            // "" → "
                inQuotes = false                                          // закрывающая кавычка; ch обрабатываем ниже
            }
            if (inQuotes) {
                if (ch == '"') afterQuote = true else field.append(ch)    // \r и \n внутри кавычек сохраняются
                continue
            }
            if (afterCr) { afterCr = false; if (ch == '\n') continue }    // CRLF = один перевод строки
            when (ch) {
                '"'       -> if (field.isEmpty()) inQuotes = true else field.append(ch)
                delimiter -> endField()
                '\n'      -> endRow()
                '\r'      -> { endRow(); afterCr = true }                 // одиночный CR — тоже перевод строки
                else      -> field.append(ch)
            }
        }
        if (field.isNotEmpty() || row.isNotEmpty()) endRow()              // файл без завершающего перевода строки
    }
}
```

Это эскиз: исполнитель пишет реализацию сам и проверяет её фикстурами из [13.6](#136-тесты)
(включая `""`, разделитель и переводы строк внутри кавычек, CR, CRLF, LF, пустые строки,
пустое последнее поле, файл без завершающего перевода строки). Кавычка посреди незакавыченного
поля (`ab"c`) считается обычным символом.

Ограничения: файл ≤ 20 МБ, поле ≤ 4 КБ, строк ≤ 200 000. Превышение — отказ с внятным текстом,
а не `OutOfMemoryError`.

### Маппинг колонок

Сначала по заголовку (регистр и пробелы игнорируются), словарь синонимов:

| Поле | Распознаётся как |
|---|---|
| дата/время | `дата и время`, `дата`, `время`, `datetime`, `date`, `time`, `timestamp`, `метка времени` |
| САД | `верхнее`, `сад`, `систолическое`, `sys`, `systolic`, `sbp`, `upper` |
| ДАД | `нижнее`, `дад`, `диастолическое`, `dia`, `diastolic`, `dbp`, `lower` |
| пульс | `пульс`, `чсс`, `pulse`, `heart rate`, `hr`, `bpm` |
| рука | `рука`, `arm`, `hand` |
| теги | `самочувствие`, `теги`, `tags`, `symptoms` |
| комментарий | `комментарий`, `заметка`, `примечание`, `comment`, `note`, `notes` |
| не импортировать | `статус`, `status` (статус всегда вычисляется по текущим порогам) |

**Приоритет колонок даты/времени** (их может быть несколько, наш экспорт содержит все три):
1. Колонка `метка времени` / `timestamp` — если есть и в строке разбирается, берётся она (ISO 8601 со
   смещением, без потерь). Остальные колонки даты/времени игнорируются.
2. Иначе пара `дата` + `время` — склеиваются в одно значение.
3. Иначе одна колонка `дата и время` / `datetime` / `date`.

**Теги** из колонки `самочувствие`/`tags` разбиваются по « · », `,` или `;`; каждый элемент
сопоставляется с русской подписью или ключом `Tag` без учёта регистра. Нераспознанные элементы
переносятся в комментарий.

Если заголовка нет (наш случай) — позиционная эвристика по первым 20 строкам:

1. Поле, которое в ≥ 80% строк разбирается как дата/время → дата. Если таких два — первое
   считается датой, второе временем.
2. Три первых целочисленных поля слева направо, попадающие в диапазоны `50…300`, `30…200`,
   `25…250`, → САД, ДАД, пульс. Дополнительная проверка: в ≥ 80% строк первое > второго.
   Если целочисленных полей только два — САД и ДАД, пульс не указан (`null`).
3. Поле со значениями из множества {левая, правая, left, right, л, п} → рука.
4. Остальные текстовые поля → комментарий (несколько склеиваются через « · »).

Результат эвристики **всегда показывается пользователю** в предпросмотре и правится вручную
(выпадающий список на каждую колонку). Автоматика не угадывает молча.

### Разбор даты и времени

Поддерживаемые форматы (по порядку попыток):

```
dd.MM.yyyy HH:mm[:ss]      ← референсный файл
dd.MM.yy HH:mm[:ss]
yyyy-MM-dd HH:mm[:ss]
yyyy-MM-dd'T'HH:mm[:ss][±HH:mm]   ← ISO, в том числе наш экспорт
dd/MM/yyyy HH:mm[:ss]
MM/dd/yyyy hh:mm a
dd.MM.yyyy                  (время → 12:00, помечается в отчёте)
```

**Двузначный год:** `yy` ≤ текущий год + 1 → 20yy, иначе 19yy.

**Неоднозначность `dd/MM` ↔ `MM/dd`:** сканируется весь файл. Если хотя бы в одной строке
первое число > 12 — порядок `dd/MM`; если второе > 12 — `MM/dd`; если ни одного (все даты
до 12-го числа) — в предпросмотре появляется переключатель «День.Месяц / Месяц.День»
со значением по умолчанию из локали. Это единственный случай, когда импорт задаёт вопрос.

**Часовой пояс:** в файле его нет. Время трактуется как локальное в **текущей зоне устройства**;
в `tz_offset` записывается смещение этой зоны **на тот момент** (не на сегодня) — иначе записи
из-под перехода на зимнее время сдвинутся на час. В предпросмотре строка:
«Время считается местным (UTC+03:00)».

Будущее время допускается при импорте с пометкой в отчёте (чужая программа могла писать
с другой зоной), но не далее +24 ч; дальше — ошибка строки.

### Эвристика руки и тегов

Колонки «рука» в файле нет, но слово часто есть в комментарии (`"левая"`).

- Переключатель в предпросмотре: **«Определять руку по комментарию»** (по умолчанию включён).
- Срабатывает только на **целое слово** из белого списка (без учёта регистра, границы слова —
  начало/конец строки, пробел или пунктуация):
  `левая, левой, левую, лев, л` → LEFT; `правая, правой, правую, прав, п` → RIGHT; `left` / `right`.
  Поиск по корню **не** используется: «правильно», «направление», «поправка» руку не задают.
- Если в комментарии есть слова и для левой, и для правой — рука не определяется.
- Комментарий при этом **не изменяется** — текст врача/пользователя не трогаем.
- Если не определилось — рука = значение `last_arm` из настроек, и в отчёте строка:
  «Для 26 записей рука не указана, проставлена «Левая»».
- Комментарий, целиком совпавший с названием известного тега («Головная боль»), переносится в теги.
  Иначе остаётся комментарием. Комментарий длиннее 120 символов обрезается, в отчёте — счётчик.

### Валидация строк

Та же, что для ручного ввода ([03.7](03-data-model.md#37-валидация-на-входе-в-data-слой)):
`sys in 50..300`, `dia in 30..200`, `pulse in 25..250`, `sys > dia`.

Поведение: невалидная строка **пропускается**, а не роняет импорт. В отчёте — номер строки
и причина. Первые 10 ошибок показываются текстом, остальные — счётчиком, полный список
выгружается в текстовый файл кнопкой «Сохранить отчёт».

Пустой пульс — допустим (чужие программы его не всегда пишут): в базу пишется `NULL`
(колонка `pulse` nullable с первой версии схемы, [03.2](03-data-model.md#32-room-схема)).
В UI такой пульс не отображается, в средний пульс не входит. Непустой пульс проверяется
диапазоном `25..250` как обычно.

### Стратегия слияния и дедупликация

Как при импорте бэкапа ([08.3](08-export-backup.md#импорт)): **Добавить к имеющимся** / **Заменить всё**.

Дубль — совпадение **всех четырёх**: `takenAt` с точностью до минуты, `sys`, `dia`, `pulse`
(`NULL` равен `NULL`). Сравниваются только неудалённые записи.
Поэтому пара `06:49 118/83/70` и `06:50 121/86/73` из референсного файла — две разные записи,
а повторный импорт того же файла добавит 0 записей.

Комментарий и рука в сравнение не входят: иначе повторный импорт после правки комментария
создаст дубль.

Вся операция — одна транзакция Room. Прерывание не оставляет полуимпорт.

### Отчёт

```
Импортировано 27 измерений
Пропущено дублей: 0
Строк с ошибками: 0
Рука определена по комментарию: 1
Рука не указана, проставлена «Левая»: 26
Период: 07.10.2026 — 20.10.2026
```

## 13.3 Экспорт

Один формат. Никакого выбора разделителя и кодировки в UI — выбор здесь означает,
что половина пользователей получит файл, который у них не открывается.

### Спецификация

| Свойство | Значение | Почему так |
|---|---|---|
| Кодировка | UTF-8 **с BOM** | Без BOM русский Excel показывает кракозябры |
| Разделитель | `;` | ru-RU/европейский Excel раскладывает `;` по колонкам; `,` оставляет одной строкой. Google Sheets определяет сам |
| Переводы строк | CRLF | Ожидание Excel и Windows-блокнота |
| Кавычки | по необходимости: поле содержит `;`, `"`, CR/LF или начинается/кончается пробелом | Файл остаётся читаемым глазами |
| Экранирование кавычки | `""` (RFC 4180) | |
| Заголовок | есть, по-русски | Файл идёт человеку (врачу) |
| Метаданные | строки `#` перед заголовком | Статус без порогов непонятен |
| Имя файла | `davlenie_2026-09-20_2026-10-20.csv` | Латиница: не все мессенджеры дружат с кириллицей в именах |

> Отклонение от строгого RFC 4180 — только разделитель. Это осознанная цена за то, что файл
> открывается двойным кликом у целевой аудитории. Наш импорт разделитель определяет сам,
> поэтому обратная совместимость не страдает.

### Структура

```
# Дневник давления — экспорт 20.10.2026
# Период: 07.10.2026 — 20.10.2026, измерений: 27
# Уровни: повышенное от 135/85, пониженное до 100/60, пульс в норме 50–90
# Статус рассчитан по этим уровням на дату экспорта
Дата;Время;Верхнее;Нижнее;Пульс;Рука;Статус;Самочувствие;Комментарий;Метка времени
07.10.2026;06:48;117;77;80;Левая;В норме;;вчера 1-й день препарата;2026-10-07T06:48:00+03:00
10.10.2026;09:51;131;87;84;Левая;Повышенное;После нагрузки;суббота, до приёма;2026-10-10T09:51:00+03:00
```

Решения по колонкам:

- **`Дата` и `Время` раздельно** — так Excel и человек сортируют и фильтруют без боли.
- **`Метка времени` последней колонкой** — ISO 8601 со смещением. Это то, что делает экспорт
  **без потерь**: при обратном импорте читается она, а не человеческие колонки, поэтому
  часовой пояс и минуты не плывут. Пользователь её не видит, пока не прокрутит вправо.
- **`Статус`** — текстом, посчитанный по порогам на момент экспорта; пороги — в шапке `#`.
  Без этого врач не поймёт, почему 136/80 — «Повышенное».
- **`Самочувствие`** — теги через « · ».
- Пустые значения — пустое поле, не `—` и не `null`.

### Диапазон и доставка

Выбор периода: 7 / 30 / 90 дней / всё время / произвольный.
Отдача файла: `ACTION_CREATE_DOCUMENT` (сохранить) и `ACTION_SEND` через `FileProvider` (отправить).
Разрешения на хранилище не нужны.

### Гарантия round-trip

Golden-тест: экспорт всей базы → импорт в чистую базу → сравнение множеств записей
(время с точностью до минуты, САД, ДАД, пульс, рука, теги, комментарий) → полное совпадение.
Это главный тест обоих форматов; он же ловит регрессии экранирования.

## 13.4 Экран импорта

Полноэкранный, нижняя навигация скрыта (как «Уровни»). Вход: Настройки → «Импорт из CSV».

### Шаг 1 — выбор файла
Текст-подсказка: «Подойдёт файл из другого дневника давления или таблицы Excel.»
Кнопка «Выбрать файл» → `ACTION_OPEN_DOCUMENT`, типы `text/csv`, `text/comma-separated-values`,
`text/plain`, `application/vnd.ms-excel`, `*/*` в конце списка (многие провайдеры отдают
CSV как `application/octet-stream`).

### Шаг 2 — предпросмотр и маппинг
- Карточка «Файл»: имя, число строк, определённые кодировка и разделитель; «Изменить» раскрывает выбор.
- Таблица первых 5 строк с заголовками-селекторами колонок (`Дата и время`, `Верхнее`, …, `Не импортировать`).
- Переключатель «Определять руку по комментарию».
- Переключатель порядка `День.Месяц / Месяц.День` — только при неоднозначности.
- Строка-итог: «Распознано 27 строк, ошибок 0». При ошибках — «Показать ошибки».

### Шаг 3 — стратегия
Две карточки-варианта: «Добавить к имеющимся» (рекомендуется, с пояснением про дубли)
и «Заменить все данные» (с предупреждением цветом `hi` и подтверждением).

### Шаг 4 — результат
Отчёт из [13.2](#отчёт), кнопки «Открыть дневник» и «Сохранить отчёт».

Разбор и запись — в `WorkManager` (не в `viewModelScope`): файл на 200 000 строк
не должен отменяться поворотом экрана. Прогресс — определённый, по прочитанным байтам.

## 13.5 Ошибки и тексты

| Ситуация | Текст пользователю |
|---|---|
| Файл не читается / нет прав | «Не удалось открыть файл. Попробуйте выбрать его заново.» |
| Пустой файл | «В файле нет данных.» |
| > 20 МБ | «Файл слишком большой — больше 20 МБ.» |
| Не распознан ни один столбец с числами | «Не похоже на дневник давления: не нашлись столбцы с верхним и нижним значением.» |
| Не разобралась ни одна дата | «Не удалось распознать дату. Выберите столбец с датой вручную.» |
| Часть строк с ошибками | «Импортировано 1 180 из 1 240. 60 строк пропущено — показать?» |
| Все строки — дубли | «Эти измерения уже есть в дневнике.» |
| Ошибка записи в базу | «Не удалось сохранить. Данные не изменились.» (транзакция откатилась) |

Тон: что произошло и что сделать. Без слов «парсинг», «валидация», «формат CSV невалиден».

### Обязательные проверки

- Определение разделителя на всех фикстурах.
- Определение кодировки: UTF-8 с BOM, без BOM, Windows-1251.
- Парсер RFC 4180: `""` внутри поля, разделитель внутри кавычек, CRLF внутри кавычек,
  пустое последнее поле, файл без завершающего перевода строки.
- Разбор всех форматов даты + двузначный год + неоднозначность `dd/MM`.
- Дедупликация: та же минута с другими значениями — две записи; полное совпадение — одна.
- Round-trip экспорт → импорт на сгенерированной базе из 1 000 записей со спецсимволами
  в комментариях (`;`, `"`, перевод строки, эмодзи).
- Экспорт: BOM присутствует, CRLF, кавычки только где нужно, шапка `#` с актуальными порогами.
- Транзакционность: падение на 500-й строке из 1 000 → в базе 0 новых записей.
