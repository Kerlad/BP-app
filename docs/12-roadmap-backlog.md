# 12. Роадмап и бэклог

Оценки — в человеко-днях одного Android-разработчика среднего уровня, с учётом тестов
и ревью, но без времени дизайнера (дизайн готов) и без ожидания ревью Google Play.

Пошаговый план для исполнителя (порядок, критерии готовности) — [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md).

## 12.4 v2 — требует отдельного планирования

| Направление | Почему не раньше |
|---|---|
| Несколько профилей (муж/жена/родитель) | Миграция данных, переработка всех запросов, UI переключения профиля |
| Синхронизация через Google Drive App Folder | Появляется `INTERNET`, политика конфиденциальности, конфликты версий |
| Health Connect (чтение/запись давления и пульса) | Отдельные разрешения и ревью Play; даёт интеграцию с умными тонометрами «бесплатно» |
| Bluetooth-тонометры напрямую (Omron, Beurer) | Проприетарные протоколы, нужен парк устройств для тестов |
| Приём лекарств: список, напоминания, связь со измерениями | Это фактически второй продукт внутри первого |
| Wear OS: запись с часов | Ограниченная аудитория |
| Локализация (en, другие) | Нужны переводы медицинских формулировок с проверкой |

**Health Connect — приоритетнее прямого Bluetooth.** Через него приходят данные с умных
тонометров, которые уже умеют писать в Health Connect, без разработки под каждое устройство.

## 12.5 Что сознательно не делаем

| Фича | Почему |
|---|---|
| Измерение давления камерой/микрофоном | Недоказуемо, запрещено политиками Play, медицински вредно |
| Любая оценка «опасно/безопасно», советы по лечению | Требует сертификации как медизделие |
| Реклама и платная подписка на базовые функции | Аудитория 50+ крайне чувствительна; монетизация — разово за PDF/синхронизацию, если вообще |
| Социальные функции, шеринг в соцсети | Данные о здоровье |
| Геймификация, стрики, «достижения» | Тон продукта — «заботливый», а не «игровой»; пропущенное измерение не должно выглядеть провалом |

## 12.6 Технический долг, который допустим на старте

Фиксируем явно, чтобы он не стал сюрпризом:

1. **Монолитный `:app`** вместо 12 модулей — если так быстрее начать. Границы пакетов
   должны совпадать с будущими модулями.
2. **Теги как JSON-строка ключей** — до появления фильтра по тегам (v1.2, миграция в таблицу `reading_tags`).
3. **Статистика считается в Kotlin**, не в SQL — до периодов 90 дней / «всё время» (v1.1).
4. **Три направления темы в коде**, хотя релизится одно (Шалфей) — стоимость нулевая, удалять не надо.
5. **Нет SQLCipher** — решение заказчика принято. Если шифрование понадобится после релиза,
   потребуется миграция базы ([09.2](09-privacy-security.md#92-шифрование-локальной-базы)).

## 12.7 Реестр решений

Решения ниже имеют приоритет над остальным текстом документации. Статус «Предложено» — решение
принято исполнителем по итогам ревью ([REVIEW-2026-10-21](REVIEW-2026-10-21.md)), реализуется,
но ждёт подтверждения заказчика.

| # | Вопрос | Решение |
|---|---|---|
| 1 | Направление | **Шалфей** (Golos Text, вес цифр 700, радиус 14 dp) |

| 4 | Крэш-репорты / сторонние SDK | **Без сторонних SDK**, приоритет — лёгкий быстрый запуск |
