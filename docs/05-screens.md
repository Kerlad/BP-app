# 05. Экраны

Для каждого экрана: состояние, события, краевые случаи, что проверить. Визуальные детали
(размеры, цвета, микротексты) — в хендоффе; здесь то, чего в хендоффе нет.

Общее: 360×780 dp, статус-бар 34 dp, нижняя навигация 74 dp + жестовая полоса 22 dp,
контент между ними скроллится. `WindowInsets` обязательны — на устройствах с врезками
навигация не должна уезжать под жестовую полосу.

## 5.1 Главная (`Route.Home`)

### Состояние

```kotlin
sealed interface HomeUiState {
    data object Loading : HomeUiState
    data class Content(
        val dateLabel: String,          // "Вторник, 20 октября"
        val greeting: String,           // "Доброе утро" — всегда без имени
        val last: LastReadingUi?,       // null -> пустое состояние (нет ни одного измерения)
        val week: WeekBarsUi?,          // null только если нет ни одного измерения вообще
        val nextReminder: String?,      // "14:00 · Дневное измерение" | null -> «Напоминания выключены»
    ) : HomeUiState
}

data class LastReadingUi(
    val whenLabel: String,              // "Сегодня, 07:24"
    val sys: Int, val dia: Int, val pulse: Int?,
    val status: Status,
    val armLabel: String,               // "Левая рука"
)
```

### Приветствие

По локальному времени: 05:00–11:59 «Доброе утро», 12:00–17:59 «Добрый день»,
18:00–22:59 «Добрый вечер», 23:00–04:59 «Доброй ночи». **Имя не используется** (решение заказчика):
в хендоффе «Доброе утро, Анна» — пример макета, в приложении просто «Доброе утро».

### Карточка «7 дней»

Столбец на каждый из 7 дней: от максимального САД до минимального ДАД за день,
толщина 16 dp, скруглённые концы, цвет по статусу **средних** значений дня
(`ac` с opacity .85 для нормы, `hi`, `lo`). Средние дня классифицируются **без округления**
(`classify(Double, Double)`, как в прототипе): 134.5/80 — норма. Пунктир — порог высокого САД.
Подписи: Пн…Сб по дню недели, сегодняшний — «Сег».

Дни без измерений: столбца нет, подпись остаётся — пропуск виден. Это важно:
пустой день — тоже информация для врача.

Заголовок справа: «среднее 133/85» — среднее по всем измерениям за 7 дней
(не среднее средних по дням).

### Краевые случаи

| Ситуация | Поведение |
|---|---|
| Нет ни одного измерения | Вместо карточки последнего — приветственная карточка: «Запишите первое измерение, и здесь появится ваша динамика». Карточка «7 дней» скрыта. Кнопка «Записать давление» на месте |
| 1 измерение | Карточка последнего есть, «7 дней» показывает один столбец, подпись «среднее» = само значение |
| За последние 7 дней измерений нет, но есть более старые | Карточка «7 дней» видна: подписи 7 дней, столбцов нет, справа вместо «среднее …» — «За неделю измерений нет» |
| Все напоминания выключены | Карточка напоминания: «Напоминания выключены», шеврон ведёт на экран напоминаний |
| Последнее измерение вчера или раньше | `whenLabel` = «Вчера, 21:10» / «18 октября, 07:30» |

### Проверить
- Пороги изменены на экране «Уровни» → цвет чипа и столбцов меняется сразу после `popBackStack`.
- Переход через полночь и смена часового пояса при открытом приложении: `dateLabel`, приветствие и
  «Сегодня» обновляются (пересчёт при `ON_RESUME` + подписка на `ACTION_DATE_CHANGED` /
  `ACTION_TIMEZONE_CHANGED`, пока экран виден).

## 5.2 Новое измерение (`Route.Entry`)

Полноэкранный, нижняя навигация скрыта. Используется и для создания, и для редактирования
(`readingId != null` → заголовок «Измерение», предзаполненные поля, кнопка «Сохранить» активна сразу,
в верхней панели появляется «Удалить»). Редактирование и удаление — **MVP**; история изменений — v1.1.
«Удалить» на этом экране — с диалогом подтверждения, затем soft delete и возврат назад со snackbar
«Измерение удалено / Отменить».

### Поведение ввода

См. [06.2](06-business-logic.md#62-ввод-с-клавиатуры) — там алгоритм целиком. Коротко:
максимум 3 цифры; автопереход после 3 цифр или после 2, если первая не «1»;
backspace на пустом поле уходит в предыдущее и стирает его последнюю цифру;
`arrow_forward` — следующее поле, `check` на «Пульс» — сохранить.

### Живой статус

Показывается, когда в САД и ДАД набрано ≥ 2 цифр. До этого — «Введите значения» (`mut`/`sf`).
Подсказки: «выше 135/85» / «ниже 100/60» / «в пределах ваших уровней» — с подстановкой
актуальных порогов.

### Время измерения

Чип «Сегодня, 09:12» в MVP — текущее время, некликабельный (в режиме правки — время записи).
В v1.1 (FR-1.9) тап открывает date+time picker; запрещено будущее время; при выборе другого дня чип
показывает «18 октября, 21:40».

### Сохранение

1. Валидация ([03.7](03-data-model.md#37-валидация-на-входе-в-data-слой)). Ошибка → обводка поля `hi`,
   под сеткой полей одна строка, например «Верхнее должно быть больше нижнего».
2. Успех → `takenAt` = время измерения, `zoneOffset` = смещение текущей зоны в этот момент,
   `arm` сохраняется в DataStore как `last_arm`.
3. Черновик, теги, комментарий сбрасываются. Новая запись → переход на Главную, тост
   «Измерение сохранено» 2.4 с. Правка → `popBackStack()`, тост «Изменения сохранены».
4. Тост показывается **над нижней навигацией**, фон `ink`, текст `bg`, иконка `check_circle`.
5. Если САД ≥ 180 или ДАД ≥ 120 — после тоста диалог с нейтральной подсказкой
   ([09.6](09-privacy-security.md#критические-значения)), один раз на запись.

> В прототипе есть костыль: `t = max(now, последняя запись + 60 c)` — чтобы демо-записи не
> совпали по времени. В продакшне так **не делаем**: `takenAt` = фактическое время. Две записи
> с одинаковой минутой допустимы (контрольное измерение через минуту — нормальная практика).

### Выход без сохранения

Кнопка `close` при непустом черновике → диалог «Не сохранять измерение?» с кнопками
«Не сохранять» / «Продолжить ввод». Системная «назад» ведёт себя так же (`BackHandler`).

### Проверить
- Поворот экрана и сворачивание-разворачивание не теряют черновик.
- Длинный комментарий обрезается на 120 символах, счётчик появляется с 100-го.
- Теги прокручиваются горизонтально и не переносятся при `fontScale = 2.0`.

## 5.3 Дневник (`Route.Diary`)

### Состояние

```kotlin
data class DiaryUiState(
    val filter: DiaryFilter,                    // ALL | HIGH | NORMAL | LOW
)
// отдельно в ViewModel: val items: Flow<PagingData<DiaryItem>>   // DiaryItem = Header | Row

data class DiaryRow(
    val id: Long,
    val time: String,            // "07:24"
    val sys: Int, val dia: Int, val pulse: Int?,
    val status: Status,
    val pulseOutOfRange: Boolean,
    val note: String,            // "Повышенное · левая рука · Головная боль · после зарядки"
)
```

`note` собирается в Presentation как `[статус, "<рука> рука", ...теги, комментарий]`
через « · », пустые элементы выбрасываются, одна строка с `TextOverflow.Ellipsis`.

### Группировка

Заголовки — по локальному календарному дню измерения (с учётом `tz_offset`), сверху свежие.
Заголовки вставляются в `PagingData` через `insertSeparators`, а не считаются в composable.

### Действия со строкой

| Действие | Результат |
|---|---|
| Тап | `Route.Entry(readingId)` — редактирование |
| Свайп влево | soft delete + snackbar «Измерение удалено / Отменить» 5 с |
| Долгое нажатие | контекстное меню: Изменить, Удалить, Копировать значения |

Snackbar должен подниматься над нижней навигацией (`SnackbarHost` с `contentWindowInsets`).

### Пустые состояния

- Фильтр ничего не нашёл: «Нет измерений с такой отметкой».
- Вообще нет записей: иллюстрации нет (ассетов нет) — текст «Дневник пуст» + «Записать давление».

### Проверить
- 2000 записей: скролл 60 fps, фильтрация не вызывает подвисаний (фильтр в SQL).
- Удаление последней записи дня убирает и заголовок группы.
- «Отменить» после смерти процесса не теряет запись (soft delete в БД).

## 5.4 Графики (`Route.Charts`)

### Состояние

```kotlin
data class ChartsUiState(
    val period: Period,                 // DAYS_7 | DAYS_30
    val chart: ChartUi?,                // null -> "Мало данных"
    val stats: List<StatCell>,          // 6 ячеек, сетка 2×3
    val inRange: InRangeUi,             // процент, сегменты, счётчики
)
```

### Отрисовка

Рисуется в Compose `Canvas` (не SVG, не сторонняя библиотека графиков):
две линии, точки, пунктиры порогов, сетка. Ось Y фиксирована 50…180 мм рт. ст.,
сетка на 60/80/100/120/140/160.

Детали из прототипа, которые нужно сохранить:
- Линия САД: `ac`, толщина 2.5 dp. Линия ДАД: `mut`, 2 dp, alpha .8.
- Точки: 8 dp для 7 дней, 4 dp для 30. Точка САД перекрашивается в `hi` (диаметр +1), если
  **статус измерения** HIGH — в том числе из-за ДАД (так в прототипе).
- Подписи оси X только две: дата начала периода («14.10») и «Сегодня».
- Значения вне 50…180 **клиппируются** к границе — линия не уходит за пределы области.
  При этом в статистике («Максимум») показывается фактическое значение. Если есть
  клиппированные точки, под графиком строка: «Значения выше 180 показаны по границе».

### Статистика

Среднее, средний пульс, «Утром» (измерения до 12:00), «Вечером» (с 12:00), Максимум и Минимум
по САД с датой. Подписи числа измерений — через `plurals` («1 измерение», «3 измерения», «5 измерений»).

### Блок «В пределах ваших уровней»

Процент норм крупно цветом `ok`; полоса 12 dp из трёх сегментов hi/ok/lo, ширина пропорциональна
числу измерений, gap 2 dp; под ней счётчики. Сегмент с нулём не рисуется (и не оставляет зазор).

### Краевые случаи

| Ситуация | Поведение |
|---|---|
| 0–1 измерение в периоде | «Мало данных для графика. Нужно хотя бы два измерения», статистика и блок процентов скрыты |
| Все измерения в один день | Точки с одинаковым X — распределяются по индексу (как в прототипе: X зависит от индекса, не от времени) |
| Нет измерений утром | «Утром» показывает «—», подпись «0 измерений» |

### Проверить
- Переключение 7/30 не мигает: `AnimatedContent` с `fadeIn/fadeOut` 150 ms.
- Пунктир порога ДАД не сливается с сеткой при `hd = 80`.

## 5.5 Напоминания (`Route.Reminders`)

### Список

Карточки: время 32/`nw`, название 15/600, дни 13/`mut`, переключатель 52×32.
Выключенное напоминание — содержимое с alpha .5. Анимация ручки 150 ms.

Сортировка: по времени возрастанию, независимо от включённости.

### Действия

| Действие | Результат |
|---|---|
| Переключатель | вкл/выкл + немедленное (пере)планирование аларма |
| Тап по карточке | `Route.ReminderEdit(id)` |
| Кнопка «Добавить напоминание» | `Route.ReminderEdit(null)` |

> В прототипе кнопка просто добавляет 12:00. В продакшне — полноэкранный `ReminderEdit`:
> Material `TimePicker`, выбор дней недели (чипы Пн…Вс + пресеты «Ежедневно», «Пн – Пт»),
> поле названия. Пустой набор дней запрещён (кнопка «Готово» неактивна). Для существующего
> напоминания — кнопка «Удалить напоминание» (с подтверждением) → `rescheduleAll()`.

### Разрешения

При `POST_NOTIFICATIONS` не выданном (Android 13+) — баннер сверху: «Чтобы напоминания
приходили, разрешите уведомления» + кнопка. При отказе дважды — кнопка ведёт в системные настройки.
При отсутствии `SCHEDULE_EXACT_ALARM` — баннер «Напоминания могут приходить с задержкой»
+ переход в настройки точных будильников. Подробно — [07](07-reminders.md).

## 5.6 Уровни давления (`Route.Levels`)

Открывается круглой кнопкой `tune` с Главной. Полноэкранный, навигация скрыта.

### Содержимое

1. Пояснение: «Измерения за пределами этих значений отмечаются цветом в дневнике и на графиках.»
2. Пресеты 2×1: «135/85 — Домашние измерения», «140/90 — Измерения у врача».
   Меняют **только** высокие САД/ДАД. Активен, если оба значения совпали.
3. Группы со степперами (шаг 5):
   - Повышенное: САД ≥ (110…200), ДАД ≥ (70…130)
   - Пониженное: САД ≤ (70…120), ДАД ≤ (40…90)
   - Пульс в норме: от (30…), до (…200)
4. Переключатель «Тёмная тема».
5. Сноска: «Целевые значения согласуйте с лечащим врачом.»
6. Пункт «Настройки» с `chevron_right` → `Route.Settings` (видимый вход в настройки; в хендоффе его нет —
   оформить как строку-карточку `sf` в стиле карточки напоминания).

### Инварианты

`lowSys < highSys`, `lowDia < highDia`, `pulseLow < pulseHigh`. Степпер, который нарушил бы
инвариант, **недоступен** (кнопка с alpha .4), а не показывает ошибку: пользователь физически
не может создать противоречивые уровни.

Запись в DataStore — с дебаунсом 300 ms (пользователь жмёт «+» несколько раз подряд).
Перерисовка цветов — немедленная, из состояния экрана.

### Тёмная тема

Переключатель здесь управляет `theme_mode`: `SYSTEM → DARK/LIGHT`. В настройках ([5.7](#57-настройки))
доступны все три варианта; на этом экране — бинарно, относительно текущего состояния.

## 5.7 Настройки

Отдельный полноэкранный экран, вход — пункт «Настройки» внизу экрана «Уровни».
Долгое нажатие на `tune` **не используется**: для аудитории 50+ скрытые жесты недоступны.

**MVP:**
- Тема: Системная / Светлая / Тёмная.
- «Удалить все данные» — два диалога подтверждения, во втором кнопка «Удалить навсегда» цветом `hi`.
  Удаляет физически все записи (включая soft-deleted), очищает DataStore, отменяет алармы,
  заново создаёт три напоминания по умолчанию и открывает онбординг.
- «О приложении» (`Route.About`): полный дисклеймер ([09.6](09-privacy-security.md#96-медицинские-дисклеймеры)),
  абзац про перенос на новый телефон ([08.4](08-export-backup.md#84-миграция-на-новый-телефон)),
  версия, ссылка на политику конфиденциальности, лицензия шрифта.

**v1.1:** крупный шрифт, экспорт CSV, отчёт PDF, импорт из CSV, резервная копия ([08](08-export-backup.md)).

Нет: выбора цветового направления, имени для приветствия, согласия на крэш-репорты (решения заказчика).

## 5.7.1 Импорт из CSV (v1.1)

Четыре шага в одном полноэкранном потоке (выбор файла → предпросмотр и сопоставление колонок →
стратегия слияния → отчёт). Спецификация экрана и всех его состояний — [13.4](13-csv.md#134-экран-импорта),
тексты ошибок — [13.5](13-csv.md#135-ошибки-и-тексты).

Разбор файла идёт в `WorkManager`, а не в `viewModelScope`: импорт на 200 000 строк не должен
отменяться поворотом экрана. Перед запуском воркера файл копируется в кэш приложения — доступ
по URI из `ACTION_OPEN_DOCUMENT` может пропасть до окончания работы.

## 5.8 Онбординг (3 экрана, один раз)

1. «Дневник давления» — зачем: записывать, видеть динамику, показать врачу.
2. «Ваши уровни» — выбор пресета 135/85 или 140/90 (можно изменить позже).
3. «Напоминания» — предложить включить утреннее и вечернее + запрос `POST_NOTIFICATIONS`;
   если `canScheduleExactAlarms() == false` — пояснение и переход в настройки точных будильников
   ([07.2](07-reminders.md#72-разрешения)). Отказ не блокирует онбординг.

В конце — обязательный экран-дисклеймер с чекбоксом подтверждения
(`disclaimer_ack`, см. [09](09-privacy-security.md)): приложение не ставит диагноз
и не заменяет врача. Без подтверждения приложение не пускает дальше.

Шагов с вводом имени и согласием на крэш-репорты **нет** (решения заказчика).
