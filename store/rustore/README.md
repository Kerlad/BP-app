# Публикация в RuStore

Всё, что нужно для карточки «Дневника давления» в [RuStore Console](https://console.rustore.ru). Требования сверены с официальной справкой RuStore 14.11.2026; ссылки на страницы — в конце.

> [!NOTE]
> Тексты карточки ниже — **черновик**: перед загрузкой их утверждает владелец.

## Что лежит в этой папке

| Файл | Для какого поля | Требование RuStore |
|---|---|---|
| `icon-512.png` | Иконка | 512×512 px, PNG или JPG, до 3 МБ, без прозрачных краёв ✔ |
| `screenshots/01…08.png` | Скриншоты для телефона | от 3 штук, 9:16, не больше 2160×3840, до 3 МБ, реальный интерфейс без системных панелей ✔ (1080×1920, 140–320 КБ) |

Скриншоты — настоящие экраны из скриншот-тестов, вписанные в кадр 9:16 с фоном самого экрана. Пересобрать после изменения интерфейса: записать снимки (`./gradlew recordRoborazziDebug`), затем `python store/rustore/make_screenshots.py` из корня проекта (нужен Pillow).

**Название** (до 30 символов):

```text

```

**Краткое описание** (до 80 символов, без эмодзи):

```text
Дневник давления и пульса: быстрый ввод, графики, напоминания, отчёт для врача
```

**Подробное описание** (до 4000 символов, на русском):

```text
Дневник давления — спокойный помощник для тех, кто следит за давлением. Записать измерение можно за несколько секунд, а за один взгляд понятно, как прошла неделя.

Запись измерения
• Крупная цифровая клавиатура: верхнее и нижнее давление, пульс.
• Рука, самочувствие и свой комментарий.

Понятный статус

Дневник, графики, статистика
• Записи по дням, фильтр по статусу, правка и удаление.
• Графики за 7 и 30 дней: среднее, утро и вечер, пульс, максимум и минимум, доля измерений в пределах ваших уровней.

Напоминания

Отчёт для врача

Удобно при слабом зрении

Ваши данные остаются у вас

Приложение не ставит диагноз и не заменяет врача. При резком ухудшении самочувствия обратитесь за медицинской помощью.
```

## Разрешения

RuStore требует объяснить цель для каждого «чувствительного» разрешения (поле «Цель» в разделе разрешений версии).

| Разрешение | Категория RuStore | Что написать в поле «Цель» |
|---|---|---|
| `POST_NOTIFICATIONS` | чувствительное | Показывает напоминание об измерении давления в заданное пользователем время. Без разрешения приложение работает, но напоминаний не будет. |
| `SCHEDULE_EXACT_ALARM` | чувствительное | Напоминание об измерении давления должно прийти точно в выбранное время (например, в 08:00 до приёма лекарства). Используется только для напоминаний, которые пользователь создал сам. |
| `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`, `ACCESS_NETWORK_STATE` | безопасные | Объяснять не нужно. Последние два добавляет системная библиотека WorkManager; в сеть приложение не выходит. |

## Шаги публикации

Выполняет владелец: для этого нужны вход в аккаунт, паспорт и ключ подписи.

1. **Аккаунт разработчика.** Войти в RuStore Console через VK ID → «Создать аккаунт» → «Физическое лицо» → «Подтвердить личность»: фото паспорта и проверка лица на камеру. Регистрация бесплатная.
2. **Ключ подписи** (задача E-04 в [ROADMAP.md](../../ROADMAP.md)). Создать один раз, хранить копию ключа и пароля в двух местах вне компьютера. Потерянный ключ означает, что обновить приложение будет нельзя.

   ```bash
   keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
   ```

   Заполнить `keystore.properties` по образцу `keystore.properties.example`. Файл и ключ в git не попадают: оба указаны в `.gitignore`.
3. **Сборка.** Для RuStore проще загружать **APK**: для AAB RuStore требует отдельно выгрузить ключ подписи приложения инструментом PEPK.

   ```bash
   BP_VERSION_CODE=62 BP_VERSION_NAME=1.1.0 ./gradlew assembleRelease
   ```

   Готовый файл: `app/build/outputs/apk/release/app-release.apk`. Проверить подпись: `apksigner verify --print-certs app-release.apk`.
4. **Новое приложение** в консоли: загрузить APK, заполнить карточку по разделу выше, указать цели разрешений, категорию, возраст, контакты, политику.
5. **Отправить на модерацию.** Обычно она занимает до 3 дней.

Каждое следующее обновление нужно подписывать **тем же ключом**, а `versionCode` должен быть больше предыдущего. Если позже будет публикация в Google Play, RuStore советует подписывать одним сертификатом во всех магазинах.

## Открытые вопросы

- **Уведомление об обновлении.** В требованиях RuStore сказано: если приложение установлено из RuStore и вышла новая версия, пользователь должен получить уведомление с предложением обновиться через RuStore. Для этого обычно подключают RuStore SDK, а ему нужен интернет. У нас интернета нет по замыслу (правило проекта: нет разрешения `INTERNET`). Перед подачей стоит спросить support@rustore.ru, относится ли требование к офлайн-приложению.
- **Персональные данные.** RuStore просит разработчиков, работающих с персональными данными, быть зарегистрированными операторами. Наши данные не покидают телефон и до разработчика не доходят (это сказано в политике). Если модерация спросит, ответ: разработчик данные не получает и не обрабатывает.
